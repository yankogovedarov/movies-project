# Итерация 44 — Бъг 30 (части 1+3): три независими флага 👍 👎 ⚠

## Контекст

[docs/Отразени бъгове.md:735](../Отразени%20бъгове.md#L735) — **Бъг #30**, втората половина
(част 2 е в [Итерация 43](Итерация%2043%20-%20Бъг%2030%20(2)%20без%20превод.md)):

> Направи иконките за DnD на Like, за изтриване -> Unlike.
> Направи нов статус и филтър - грешни субтитри.

Днес статусите са три — `new`, `started` и ръчният `for_dnd` (бутон `D` в реда и във филтъра,
етикет `DnD` в колоната „Статус"), а единственият флаг е `for_deletion` (🗑, параметър `del`,
Итерация 37).

**Решения на потребителя (при планирането):**
- „За DnD", „За изтриване" и „Грешни субтитри" са **три независими флага** — всеки се вдига и
  сваля сам и се комбинира с всичко останало, вкл. 👍 и 👎 едновременно. „За DnD" **престава да е
  статус**.
- Икони: 👍 За DnD · 👎 За изтриване · ⚠ Грешни субтитри.

**Резултат:** два статуса (Нова · Стартирана, бутони ○ ▶) и три флага (👍 👎 ⚠) — в реда, в
лентата, в 🎲 и в запомненото състояние.

## Проектантски решения

1. **Флаговете са булеви колони, всеки с отделен параметър** — както `for_deletion`/`del`:
   `media.for_dnd` + `dnd=all|yes`, `media.wrong_subs` + `subs=all|yes`; запомнят се в
   `ui_prefs.dnd_filter` и `ui_prefs.subs_filter`. `yes` стеснява списъка, а активните флаг филтри
   се комбинират помежду си и със статуса (И).
2. **Бившите „За DnD" медии** (миграция 000009) получават `for_dnd = 1`. Статусът им става
   `started`, ако имат поне едно стартиране, иначе `new` — определението на двата автоматични
   статуса (Проект филми.md §3). Преходът се вписва в `status_changes` (`for_dnd → started|new`),
   както в 000007. Запомнен `status_filter = 'for_dnd'` става `status = all` + `dnd = yes` — същият
   изглед, но вече през флага. `down` е no-op (като 000007): обратното би изтрило флаговете, а пътят
   назад е стартовият backup.
3. **`ChangeStatus` приема само `new|started`** — `for_dnd` вече е махнат статус и връща `400`
   (allowlist-ът от Итерация 41).
4. **Флаговете се виждат само като подчертан бутон в реда** (`filter-active`, както 🗑 днес).
   Колоната „Статус" показва само „Нова"/„Старт" — зеленото `DnD` изчезва.
5. **Подредба:** ред ○ ▶ 👍 👎 ⚠; лента „филтър:" [папка] ◎ ○ ▶ ↕ 👍 👎 ⚠ (флаговете се
   събират след ↕).
6. **Един общ handler за флаговете.** Тялото на днешния `SetForDeletion` става `setFlag(c, update)`;
   `SetForDnd`, `SetForDeletion` и `SetWrongSubs` само го викат със своята заявка. Маршрути
   `POST /media/:id/for-dnd`, `/for-deletion` (без промяна), `/wrong-subs`; `value` = `1` / `0`.
7. **Линковете на лентата се строят от една стойност `templates.Filters`** (статус, диск, сорт,
   посока, търсене, трите флага, папка) с метод `Href()` и малки методи, които копират `Filters` и
   сменят едно поле. Без това всеки от ~14-те линка би лепил девет низа на ръка — точно при
   добавянето на два параметъра някой линк се изпуска (тестовете „запазва се от другите филтри" го
   хващат, но структурата го предотвратява). `Href()` **запазва днешното поведение** за `q`
   (суров) — екранирането е [Бъг #31](../Открити%20бъгове.md) и тогава ще се поправи на едно място.
   `RandomNew` си строи redirect адреса сам (няма `sort`/`dir`), само получава `dnd` и `subs`.
8. **Стартирането не пипа флаговете** — `StartMedia` и `RandomNew` сменят само `new → started`;
   `UpsertMedia` не ги пише, затова пресканирането ги пази (като `for_deletion`).

## Промени

### 1. DB — `internal/db/migrations/000009_independent_flags.{up,down}.sql`

```sql
-- up
ALTER TABLE media ADD COLUMN for_dnd INTEGER NOT NULL DEFAULT 0;
ALTER TABLE media ADD COLUMN wrong_subs INTEGER NOT NULL DEFAULT 0;
ALTER TABLE ui_prefs ADD COLUMN dnd_filter TEXT NOT NULL DEFAULT 'all';
ALTER TABLE ui_prefs ADD COLUMN subs_filter TEXT NOT NULL DEFAULT 'all';

UPDATE media SET for_dnd = 1 WHERE current_status = 'for_dnd';

INSERT INTO status_changes (media_id, from_status, to_status)
SELECT id, 'for_dnd',
       CASE WHEN EXISTS (SELECT 1 FROM start_events se WHERE se.media_id = media.id)
            THEN 'started' ELSE 'new' END
FROM media WHERE current_status = 'for_dnd';

UPDATE media SET current_status =
       CASE WHEN EXISTS (SELECT 1 FROM start_events se WHERE se.media_id = media.id)
            THEN 'started' ELSE 'new' END
WHERE current_status = 'for_dnd';

UPDATE ui_prefs SET status_filter = 'all', dnd_filter = 'yes' WHERE status_filter = 'for_dnd';
-- down: no-op (SELECT 1;) + коментар защо
```
