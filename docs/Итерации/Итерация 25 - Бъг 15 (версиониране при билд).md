# Итерация 25 — Бъг 15 (част 3): авто-версиониране при билд + показване в конзолата

## Context

Трета (последна) подточка на Bug #15:

> да се добави увеличаване на версия при всеки следващ билд. версията да се показва в конзолата при стартиране на приложението.

Към момента няма никаква концепция за версия в кода или build-а.

## Дизайн

- **Семантична версия** `v1.0.0` (вече маркирана в продукция, commit d44ab4b) — държи се като Taskfile променлива `VERSION`.
- **Build номер** — монотонен брояч, увеличаван при **всеки** `task build`. Съхранява се във файл `.build-number` в корена на проекта.
  - Файлът е **gitignored** → без git churn при всеки билд; per-machine брояч (подходящо за локално, single-user приложение на диск).
  - Не чупи clean clone: ако файлът липсва, брои се от `0` → първи билд = `1`.
- **Инжектиране** чрез `-ldflags -X` (без CGo, остава статичен binary) — без `//go:embed`, за да няма проследяван файл, който се променя при всеки билд.
- **Показване** — `slog.Info` при старт (отива на stdout = конзолата + лог файла), **преди** тежкото сканиране на диска.
- **`--version` флаг** (малка добавка) — отпечатва версията и излиза веднага, **преди** `disk.Discover`. Прави версията проверяема без пълно дисково сканиране и е конвенционален начин да се изложи версията.

## Промени

### 1. Нов `cmd/bumpbuild/main.go`
- Чете `.build-number` (ако липсва → `""`), изчислява следващия чрез чиста функция `nextBuildNumber(prev string) string`, записва го обратно, и **печата само числото** на stdout (грешки → stderr).
- `nextBuildNumber`: парсва int; при грешка или отрицателно → третира като `0`; връща `n+1` като низ.

### 2. Нов `cmd/bumpbuild/main_test.go` (TDD — пръв)
- `"0" → "1"`, `"" → "1"`, `"  7  " → "8"`, `"abc" → "1"`, `"-3" → "1"`.

### 3. `Taskfile.yml` — task `build`
```yaml
build:
  desc: Build static executable into bin/ (auto-increments build number)
  vars:
    VERSION: v1.0.0
    BUILD:
      sh: go run ./cmd/bumpbuild
  cmds:
    - go build -ldflags "-X main.version={{.VERSION}} -X main.buildNumber={{.BUILD}}" -o bin/movietracker.exe ./cmd/movietracker
```

### 4. `cmd/movietracker/main.go`
- Package-level: `var version = "dev"` и `var buildNumber = "0"` (заместват се от ldflags при билд).
- В началото на `main()` (преди `disk.Discover`): ако `os.Args` съдържа `--version`/`-v`/`version` → `fmt.Printf("Movie Tracker %s (build %s)\n", version, buildNumber)` и `return`.
- След setup на logger-а (преди дисковото сканиране): `slog.Info("Movie Tracker", "version", version, "build", buildNumber)`.

### 5. `.gitignore`
- Добавяне на `.build-number`.

## Верификация

(`task` не е инсталиран на машината → проверката се прави с еквивалентните Go команди.)

1. `go test ./...` — зелено (вкл. новите `nextBuildNumber` тестове).
2. `go run ./cmd/bumpbuild` два пъти → стойността в `.build-number` расте (напр. `1`, после `2`).
3. `go build -ldflags "-X main.version=v1.0.0 -X main.buildNumber=42" -o bin/movietracker.exe ./cmd/movietracker` после `bin/movietracker.exe --version` → отпечатва `Movie Tracker v1.0.0 (build 42)` и излиза (без дисково сканиране).
4. (По избор) `task build` в среда с инсталиран go-task → build номерът се увеличава при всяко изпълнение.
