# Итерация 37 — Бъг 22: флаг „за изтриване" + филтър в регистъра

## Контекст

[docs/Открити бъгове.md:597](../Открити%20бъгове.md#L597) — **Бъг #22**:

> да има нов флаг - "за изтриване", както и нов филтър в рефистъра.

Днес медия има само `current_status` (нова / стартирана / завършена) и `translation_type`.
Няма как да се отбележи „този файл го чистим при следващото освобождаване на място", нито
да се извади списък само с такива файлове.

**Резултат:** 🗑 бутон във всеки ред (колона „Функции") превключва флага, а 🗑 бутон в
групата „филтър:" превключва списъка към „само маркираните за изтриване".

**Решения на потребителя (уточнени):**
- Филтърът е **в съществуващата група `.filter-btns`** („филтър:"), не в отделна група.
- Бутонът в реда е **в колона „Функции" (`td.actions`)**, не в нова колона.
- Визуализация: **само подчертан 🗑 бутон** (`filter-active`) — без приглушен/зачертан ред
  и без ред в детайлния изглед.

**Проектантско решение (следствие):** флагът е **отделен query параметър `del`**, а не нова
стойност на `status` — иначе „за изтриване" би изключвало взаимно със „Завършена".
Бутонът обаче се рендира вътре в групата `.filter-btns`, точно както прави дисковият
toggle `↕`, който също е отделен параметър в същата група.

## Промени

### 1. DB — нова колона

Миграция `internal/db/migrations/000004_add_for_deletion.{up,down}.sql`:

```sql
ALTER TABLE media ADD COLUMN for_deletion INTEGER NOT NULL DEFAULT 0;
```

Булевите в тази схема са `INTEGER` (виж `on_disk` → `OnDisk int64`), затова няма override в
`sqlc.yaml`. Индекс не се добавя — филтрирането е в Go, както при `translation_type`.

### 2. sqlc заявки — `internal/db/queries.sql`

- `for_deletion` се добавя в изричните колонни списъци на `ListOnDiskMedia`, `ListAllMedia`
  и `GetMediaByID`.
- Нова заявка по модел на `UpdateTranslationType`:
  ```sql
  -- name: UpdateForDeletion :exec
  UPDATE media SET for_deletion = ? WHERE id = ?;
  ```
- `UpsertMedia` **не** се пипа — `DO UPDATE SET` не изброява новата колона, така че повторно
  сканиране пази ръчно вдигнатия флаг.

### 3. Handlers — `internal/web/handlers.go`

- `filterMedia` получава нов параметър `delFilter`; при `del=yes` остават само
  `m.ForDeletion == 1`.
- `Index`: `delFilter := c.DefaultQuery("del", "all")` → `filterMedia` + `templates.ListPage`.
- `RandomNew`: `c.PostForm("del")` с default `"all"`; двата redirect-а получават `&del=%s`.
- Нов handler `SetForDeletion` по модела на `SetTranslationType`: parse `:id` →
  `c.PostForm("value")` (`"1"`/`"0"`) → `UpdateForDeletion` → при HTMX рендира само реда,
  иначе `303` към `/`. Използва `db.FetchSingleMediaStats`.

### 4. Route

- `cmd/movietracker/main.go` → `r.POST("/media/:id/for-deletion", h.SetForDeletion)`.
- `newRouter` в `internal/web/handlers_test.go` дублира таблицата с маршрути и е изостанал
  (липсваше му и `/translation-type`) — добавят се и двата маршрута.

### 5. Шаблони

- `templates/helpers.go`: `sortBtnHref(...)` получава параметър `del`; нови helper-и
  `delToggleValue(current string) string` и `forDeletionToggleValue(current int64) string`.
- `templates/list.templ`: `ListPage(...)` получава `delFilter`; всички href-ове в „филтър:",
  „превод:" и „сорт:" носят `&del=`; скрито поле `del` в търсещата и в 🎲 формата;
  нов 🗑 филтър бутон последен в `.filter-btns`; нов 🗑 бутон в `td.actions` преди `ℹ`;
  ширината на `td.actions` расте на `10.4rem` + правило за подчертан активен 🗑.

**Заглавието на филтър бутона умишлено не съдържа думата „кликни"** —
`tests/e2e/test_filters.py` таргетира дисковия toggle с `a.filter-btn[title*='кликни']`
и очаква точно едно съвпадение.

Детайлният изглед не се променя.
