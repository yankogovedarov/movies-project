# Итерация 20: Сортиране по дата на файла

## Цел

Сортирането по "дата на добавяне" (`?sort=added`) да използва **реалната дата на създаване на файла** от файловата система, вместо `created_at` от базата данни (кога файлът е бил сканиран за пръв път).

## Мотивация

`created_at` в DB отразява кога скенерът е открил файла — т.е. зависи кога потребителят е стартирал приложението. Дата на създаване на файла отразява кога файлът реално е поставен на диска, което е по-смислено за сортиране по "нов/стар".

## Промени

### Нова миграция

- `task migrate-new -- add_file_created_at`
- Добавя колона `file_created_at TIMESTAMP NULL` в таблица `media`
- NULL е допустим — съществуващи записи се попълват при следващо сканиране

### Scanner (`internal/scanner/scanner.go`)

- При обход на файлове: чете creation time чрез `syscall.Win32FileAttributeData` (Windows-specific, тъй като приложението е Windows-only)
- Helper функция `fileCreatedAt(path string) (time.Time, error)` — капсулира syscall логиката
- При `INSERT` на нов запис: попълва `file_created_at`
- При UPDATE на съществуващ запис (re-scan): попълва `file_created_at` ако е NULL

### sqlc (`internal/db/queries.sql` + генериран код)

- `UpsertMedia` заявката включва `file_created_at` параметър
- `ListAllMedia` и `ListOnDiskMedia` — добавят `file_created_at` в SELECT
- DB model `Medium` получава ново поле `FileCreatedAt sql.NullTime`

### Handler (`internal/web/handlers.go`)

- `case "added"` в сортиращия switch използва `FileCreatedAt` (с fallback към `CreatedAt` ако NULL):
  ```go
  case "added":
      sort.Slice(media, func(i, j int) bool {
          ti := media[i].FileCreatedAt.Time
          if !media[i].FileCreatedAt.Valid {
              ti = media[i].CreatedAt
          }
          tj := media[j].FileCreatedAt.Time
          if !media[j].FileCreatedAt.Valid {
              tj = media[j].CreatedAt
          }
          return ti.After(tj)
      })
  ```

### Тестове

- Unit тест за `fileCreatedAt` helper (може да се пропусне на CI без Windows — build tag)
- Обновен unit тест за `sort=added` в `handlers_test.go`: проверява реда при MediaWithStats с попълнен `FileCreatedAt`
- Goquery тест: `?sort=added` с различни `FileCreatedAt` стойности → правилен ред на редовете

## Архитектурно решение

Windows `syscall.Win32FileAttributeData.CreationTime` дава надеждна дата на създаване. Тъй като приложението е Windows-only (`.exe` на Windows диск), няма нужда от cross-platform абстракция. Кодът се изолира в `internal/scanner/file_time_windows.go` с build tag `//go:build windows`.

Fallback към `CreatedAt` при NULL гарантира, че съществуващите записи се сортират разумно преди следващо сканиране.

## Дефиниция за готово

- `task generate` → без грешки
- `task test` → всички тестове минават (вкл. нови)
- `task build` → без грешки
- `/?sort=added` сортира по `file_created_at` (а не по `created_at` от DB)
- Записи с NULL `file_created_at` не предизвикват паника — fallback работи
- При ново сканиране `file_created_at` се попълва за нови и за непопълнени стари записи
