# Итерация 24 — Бъг 15 (части 1+2): случаен филм от филтрираните, без презареждане

## Context

Bug #15 има три подточки. Тази итерация покрива първите две (свързани — един и същ handler/форма):

1. **🎲 да избира от филтрираните филми** — напр. филтър „Янко" → случаен от Янко-филмите.
2. **🎲 да не презарежда страницата и да не сменя текущия филтър.**

### Текущо състояние (преди итерацията)

- Част 1 е **функционално реализирана** в Итерация 22: `RandomNew` чете `status/disk/q/trans` от POST формата и извиква `filterMedia(...)`. **Няма обаче нито един тест** за `RandomNew`.
- Част 2 **липсва**: `RandomNew` прави `c.Redirect(303, ...)` → пълно презареждане на страницата при всяко натискане на 🎲.
- **Скрит дефект:** `RandomNew` сменя статуса на избрания на `started` **безусловно**. Ако филтрираш по „Янко" и пуснеш случаен, филмът губи статус `completed_yanko` и **изпада от филтъра** — точно това, което част 2 иска да избегне. `StartMedia` за сравнение сменя на `started` само ако текущият статус е `new`.

## Решение

### 1. `internal/web/handlers.go` — `RandomNew`

- Запазва четенето на `status/disk/q/trans` + `filterMedia(...)` (вече работи).
- **Статус логика → като `StartMedia`:** винаги `InsertStartEvent`; статус се сменя на `started` **само** ако текущият е `new`. Така вече-завършен филм остава в активния филтър.
- **HTMX отговор** (`HX-Request: true`): връща `MediaRowOOB(chosen)` (ред с `hx-swap-oob="true"`) + flash фрагмент; HTTP 200, **без redirect**.
- **Fallback без HTMX:** запазва текущия `c.Redirect` с query-параметрите.
- **Без кандидати:** при HTMX → flash „Няма филми за избор"; иначе redirect (както сега).

### 2. `templates/list.templ`

- **🎲 форма:** `hx-post="/media/random-new/start"`, `hx-target="#flash"`, `hx-swap="innerHTML"` (hidden inputs `status/disk/q/trans` остават; `action`/`method=POST` остават като graceful fallback).
- **`<tr id="media-{id}">`** на реда (target за OOB swap).
- **Рефактор:** извличане на клетките в `templ mediaRowCells(m)`. `MediaRow(m)` (нормален ред) и нов `MediaRowOOB(m)` (`<tr … hx-swap-oob="true">`) го ползват. Сигнатурата на `MediaRow(m)` **остава непроменена** → съществуващите goquery тестове не се чупят.
- **`<div id="flash" class="flash">`** регион (под navbar) + дискретен CSS. Показва кой филм е пуснат — важно, ако избраният ред е извън видимия екран.

### 3. `internal/web/handlers_test.go` — тестов router

- `newRouter` **не регистрира** `/media/random-new/start`. Добавя се:
  `r.POST("/media/random-new/start", h.RandomNew)`.

## Тестове (TDD — пишат се преди кода, червени → зелени)

`internal/web/handlers_test.go`:
- `TestRandomNew_PicksFromFilteredStatus` — seed смесени статуси; POST `status=completed_yanko` → избраният филм е от Янко-групата (assert чрез DB / последен start event).
- `TestRandomNew_NewBecomesStarted` — кандидат със статус `new` → след random статусът е `started`.
- `TestRandomNew_KeepsCompletedStatus` — кандидат `completed_yanko` → остава `completed_yanko` (само start count++).
- `TestRandomNew_HTMX_ReturnsOOBRow` — `HX-Request: true` → 200 + body съдържа `<tr … hx-swap-oob="true" id="media-…">`.
- `TestRandomNew_HTMX_DoesNotRedirect` — при HTMX няма 303/Location.
- `TestRandomNew_NoCandidates_HTMX` — филтър без съвпадения → 200 + flash съобщение (без redirect).

`internal/web/handlers_goquery_test.go`:
- `TestIndex_RandomForm_HasHxPost` — 🎲 формата има `hx-post` към `/media/random-new/start` + hidden inputs за `status/disk/q/trans`.
