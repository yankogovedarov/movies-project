# Итерация 33 — Бъг 19: сортиране по дата започва низходящо

## Цел

При сортиране по дата първото натискане на сорт бутона да показва **най-скорошните първи**
(низходящ ред), а второто натискане — възходящ. Важи за двата вида сортиране по дата:

- „По дата добавяне" (`sort=added`, бутон ⊕)
- „По дата завършване" (`sort=marked`, бутон ✓)

Бутонът „По последно стартиране" (`last_started`) запазва досегашното поведение
(потребителят изрично казва „двата вида сортиране по дата").

## Корен на проблема

`sortBtnHref` в `templates/helpers.go` — при клик върху **неактивен** сорт бутон
посоката винаги е `asc`. Handler-ът (`internal/web/handlers.go`) вече поддържа коректно
двете посоки чрез `dir=asc|desc` — промяна там не е нужна.

## Промени

1. **`templates/helpers.go`** — нов helper `defaultSortDir(btnSort)`: връща `desc` за
   `added`/`marked`, иначе `asc`. `sortBtnHref` вече:
   - неактивен бутон → посоката по подразбиране за този бутон;
   - активен бутон → toggle на текущата посока (без промяна спрямо досегашното).
2. **Тестове (TDD, red → green):**
   - нов `templates/helpers_test.go` — unit тестове за `sortBtnHref` (desc при първо
     натискане на датовите; toggle при активен; `asc` за останалите бутони);
   - `internal/web/handlers_goquery_test.go` — href-овете на ⊕ и ✓ на началната
     страница съдържат `dir=desc`;
   - `tests/e2e/test_sort.py` — първо кликане на ⊕/✓ → URL с `dir=desc`; второ → `dir=asc`.
3. **`Taskfile.yml`** — `VERSION: v1.3.0` → `v1.4.0`.
4. **`docs/Открити бъгове.md`** — Бъг 19 статус ✓ Завършен + ред в резюме таблицата.

Без `task generate` — `list_templ.go` вика `sortBtnHref` по име; `.templ` файловете не се пипат.
