# Итерация 35 — Бъг 20 (2): анализ на размера на exe + strip флагове

## Цел

Бъг 20 (2): „защо компилираното exe е много голямо — 28MB". Отговорът е двусъставен:
документиран анализ на причините + реално намаление чрез strip флагове при production
билд (потвърдено с потребителя; `-s -w -trimpath`).

## Анализ — защо 28.9 MB (28 934 144 байта)

По големина на приноса:

1. **`modernc.org/sqlite` + `modernc.org/libc` (~10–15 MB, доминиращ).** Pure-Go SQLite е
   механична C→Go транслация на цялата SQLite амалгамация + Go реимплементация на голяма
   част от libc. Това е цената на съзнателното решение „pure Go, без CGo → статичен binary
   без външни зависимости" (Архитектура.md, Лог на решенията). Не е дефект.
2. **Липсващи `-s -w` (~25–35% от binary-то).** Symbol table + DWARF debug информация се
   разпространяват в production exe без никаква полза за потребителя.
3. **Go runtime (~1.5–2 MB)** — неизбежен минимум.
4. **gin + validator + `bytedance/sonic` (JIT асемблер) и др.** — няколко MB.
5. **Embedded ресурси (Pico.css + HTMX + миграции) ≈ 133 KB** — пренебрежимо (~0.5%).

Фалшиви следи: `quic-go` и `mongo-driver` от `go.mod` (транзитивни на golang-migrate) НЕ
влизат в binary-то (linker dead-code elimination); `mattn/go-sqlite3` е зад CGo build tags
и при `CGO_ENABLED=0` не се компилира.

## Разгледани и отхвърлени алтернативи

- **UPX компресия (~9–12 MB):** отхвърлена — по-бавен студен старт и чести AV false
  positives (Windows Defender/SmartScreen), реален риск за exe, който пътува на преносим
  диск между 3 компютъра.
- **Връщане към `mattn/go-sqlite3` (CGo):** отхвърлено — реверс на документираното
  решение за статичен binary без C toolchain.

   - `go build -trimpath -ldflags "-s -w -X main.version=... -X main.buildNumber=..."`
   - `VERSION: v1.4.0` → `v1.5.0`

3. **`README.md`** — редове за Итерации 34–35 в таблицата (правилото за README в същия комит).
4. **`docs/Открити бъгове.md`** — секция „Реализирано (Итерации 34–35)" под Bug #20,

## Верификация (build флаговете не са unit-тестваеми)

- `task build` → размерът на `bin/movietracker.exe` спада от 28 934 144 байта към очаквани
  ~19–22 MB; реалната стойност се записва тук и в Архитектура.md.
  **Измерено: 19 888 128 байта (~19.0 MiB) — −31.3% спрямо 28 934 144.**
- `bin/movietracker.exe --version` → отпечатва `Movie Tracker v1.5.0 (build 9)` —
  доказва, че `-X` инжекцията работи заедно със `-s -w`. ✓
- Дългосрочният под (~19 MB) е присъщ на pure-Go SQLite стека — по-нататъшно значимо
  намаление изисква отхвърлените алтернативи (UPX / CGo).
- `task test` и `task test:e2e` зелени.
