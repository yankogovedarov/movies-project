# Открити бъгове

## Bug #1: Хоризонтален scroll bar при преглед на списъка

### Описание
При преглед на списъка с филми, се появява хоризонтален scroll bar, което прави интерфейса тесен и трудночетлив. Трябва да се видят всички данни (Файл, Папка, Размер, Статус) и бутоните (Пусни, Смени) без нужда от хоризонтално скролиране.

### Текущо поведение
- Таблицата се превалива отдясно
- Потребител трябва да скролира хоризонтално, за да видобутоните
- Лоша потребителска преживяност

### Очаквано поведение
- Таблицата трябва да се побира на екрана без хоризонтален scroll
- Колоните трябва да се адаптират към ширината на преглеждача
- Текстът трябва да бъде четлив

### Потенциални решения
1. **Намаляване на текст в колони** - използване на text-overflow: ellipsis за дълги имена на файлове и папки
2. **Преподредба на информация** - преместване на Папка колона на отделен ред или скриване по default
3. **Адаптивна таблица** - на малки екрани показване само на най-важната информация (Файл + Статус)
4. **Намаляване на padding/margin** - компактифициране на таблицата с Pico.css override-и

### Приоритет
Висок (влияе на основната функционалност на интерфейса)

### Статус
✓ Завършен (коригиран преди Итерация 12)

## Реализирано решение за Bug #1

### Архитектурни решения (имплементирано)
Проблемът е в таблицата, която е твърде широка за мобилен/стандартен преглеждач. Решение:

1. **Колона "Папка"** → преместване в втори ред (или скриване на малки екрани)
   - На дървето медия, папката е вече видима в UI (Folder tree)
   - За списък с всички файлове, папката е по-малко важна от името и статуса

2. **Колона "Размер"** → съкращение или font-size намаляване
   - Сейчас показва пълния размер в GB/MB
   - Може да се съкрати с по-малко decimal places

3. **Таблица** → text-overflow: ellipsis на дълги имена
   - Файловете с дълги имена (Godzilla x Kong New Empire.mkv) ще бъдат съкратени с ...
   - Tooltip (title attribute) ще показва пълното име на hover

4. **Pico.css адаптивност** → добавяне на @media queries
   - На екрани < 768px: скриване на Папка колона
   - На екрани < 1024px: съкращаване на размер колона

### Файлове за промяна

  - HTML структурата има необходимите `title` атрибути за tooltips
  - Размерът е форматиран корректно

### Имплементирани промени
1. **list.templ** — добавени CSS класове `filename`, `folder`, `size`, `status`, `actions`
2. **CSS стилове** — `text-overflow: ellipsis` за всички колони
3. **Tooltips** — `title` атрибути за Файл и Папка колони (с пълния текст)
4. **Responsive design** — `@media (max-width: 1200px)` скрива Размер, `@media (max-width: 768px)` намалява размер на шрифт
5. **Form inline** — `display: inline` за компактни бутони
6. **Таблица** — `width: 100%` и `table-layout: auto` за адаптивна ширина

## Bug #11: UI корекции — filter бутони + вертикално изместване

### Описание

Два свързани проблема:
1. Филтрите (select dropdowns) не се виждат добре в navbar-а
2. Редовете в таблицата са по-високи от очакваното; има вертикално изместване на елементите

### Решение 1 — Filter бутони

Select dropdowns заменени с 7 малки icon link бутона (`a.filter-btn`):
- `◎` Всички статуси
- `○` Нова / `▶` Стартирана / `✓` Двамата / `Я` Янко / `Л` Лиза
- `↕` Disk toggle (на диска / всички)

Активният бутон получава клас `filter-active` → оцветява се с `--pico-primary`.

### Решение 2 — Вертикално изместване (корен на проблема)

**Причина:** Pico.css v2 прилага `margin-bottom: var(--pico-spacing)` (~1rem) чрез **атрибутни селектори** с по-висок specificity:

```css
/* Pico.css v2 — specificity 0,1,0 (атрибутен селектор) */
[type=submit], [type=button], [type=reset], [role=button] {
    margin-bottom: var(--pico-spacing);
}
```

Нашият override `button { margin-bottom: 0; }` има specificity 0,0,1 (елементен селектор) и **губи** срещу Pico. Всеки `<button type="submit">` в таблицата надуваше реда с ~1rem.

**Важно:** `button { margin-bottom: 0 }` не е достатъчно — трябва да се match-нат изрично всички Pico селектори.

**Поправка в `templates/list.templ`:**

```css
button, [type=submit], [type=button], [type=reset], [role=button],
input, select, textarea { margin-bottom: 0; }
```

### Статус

✓ Завършен
 

## Bug #12: Сортиране по път/размер + посока + случаен филм

### Реализирани промени (Итерация 21)

1. **Сортиране по папка/път** — нов бутон `Пт` (`sort=path`), азбучно по `FolderRelativePath`
2. **Сортиране по размер** — нов бутон `Рз` (`sort=size`), числово по `FileSizeBytes`

   - Активният бутон показва `↑` (asc) или `↓` (desc) след иконката
   - CSS: `width: auto; min-width: 1.35rem` за активния бутон
4. **Случаен нов филм** — бутон `🎲` в navbar; `POST /media/random-new/start` избира произволна медия с `status=new`, стартира я в VLC и сменя статуса на `started`

- flash фрагмент „🎲 Стартирах: \<име\>" в регион `#flash`
- out-of-band ред `<tr hx-swap-oob="true" id="media-{id}">` — само засегнатият ред се обновява на място

Страницата не се презарежда и текущият филтър се запазва. Без HTMX има graceful fallback с redirect (query параметрите се пренасят).

**Поправен скрит дефект:** `RandomNew` вече сменя статуса на `started` само ако текущият е `new` (съгласувано с `StartMedia`). Вече-завършен филм (напр. `completed_yanko`) запазва статуса си и остава в активния филтър.

**Нов templ компонент:** `Flash(msg)`; `MediaRow` рефакториран да споделя клетките с нов `MediaRowOOB`.

**Тестово покритие:** добавени unit тестове в `handlers_test.go` (filter logic, статус логика, HTMX OOB, fallback) и goquery тест за формата в `handlers_goquery_test.go`.
