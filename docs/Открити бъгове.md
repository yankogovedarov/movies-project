## Bug #3: Липсващ endpoint GET /scan/status

### Описание
Документацията (Архитектура.md, ред 153) предвижда endpoint `GET /scan/status` за получаване на текущ статус на фоновото сканиране (за прогрес индикатор). Този endpoint не е имплементиран в Итерация 12.

### Влияние
- Потребителят не може да види дали сканирането е в прогрес
- Необходимо е за MVP-2 при по-дълги сканирания

### Потребителски сценарий
1. Потребител нажима "Сканирай"
2. Браузърът показва индикатор за прогрес (чрез polling към GET /scan/status)
3. Когато приключи, списъкът се обновява автоматично

### Приоритет
Среден (не е критично за MVP-1, но е в архитектурата)

### Статус
⚠ Незавършен (планирано за MVP-2 Итерация 13)

## Bug #5: Липсва middleware за проверка на disk availability

### Описание
Документацията (Архитектура.md, ред 202-204) предвижда middleware, което проверява дали диска е достъпен при всяка HTTP заявка. Ако диска е изваден, UI показва съобщение *"Дискът не е свързан..."*.

Това не е имплементирано.

### Влияние
- Приложението продължава да работи с грешни данни, дори след изваждане на диска
- Потребителят не получава ясна обратна връзка

### Потребителски сценарий
1. Приложението работи нормално
2. Потребител физически изваща диска
3. Следната HTTP заявка → middleware проверява диска → връща error page
4. Когато диска се върне → обновяване на страницата възстановява работата

### Приоритет
Висок (толерантност при изваждане на диска - нефункционално изискване)

### Статус
⚠ Незавършен (планирано за MVP-2)

## Bug #28: Празен списък и дърво по време на пресканиране

### Описание
`SyncScanResults` ([internal/db/sync.go](../internal/db/sync.go)) първо маркира всички медии като липсващи (`MarkAllOffDisk`) и след това записва намерените файлове една по една (`UpsertMedia`) — **без транзакция**. Докато сканирането върви, списъкът (`GET /`, режим „на диска") и дървото (`GET /tree`) показват само вече записаните медии — за кратко са празни или непълни.

Открит в Итерация 41: e2e тестовете за бутона „Сканирай" пускат асинхронно пресканиране и следващите тестове за дървото понякога се пропускат (`pytest.skip`), защото дървото е празно.

### Предложено решение
`MarkAllOffDisk` и всички upsert-и в една транзакция — четящите заявки виждат или старото, или новото състояние, никога междинното.

### Статус
⚠ Незавършен
