# Открити бъгове

## Bug #1: Хоризонтален scroll bar при преглед на списъка

### Описание
При преглед на списъка с филми, се появява хоризонтален scroll bar, което прави интерфейса тесен и трудночетлив. Трябва да се видят всички данни (Файл, Папка, Размер, Статус) и бутоните (Пусни, Смени) без нужда от хоризонтално скролиране.

### Текущо поведение
- Таблицата се превалива отдясно
- Потребител трябва да скролира хоризонтално, за да видобутоните
- Лоша потребителска преживяност

### Очаквано поведение
- Таблицата трябва да се побира на екрана без хоризонтален scroll
- Колоните трябва да се адаптират към ширината на преглеждача
- Текстът трябва да бъде четлив

### Потенциални решения
1. **Намаляване на текст в колони** - използване на text-overflow: ellipsis за дълги имена на файлове и папки
2. **Преподредба на информация** - преместване на Папка колона на отделен ред или скриване по default
3. **Адаптивна таблица** - на малки екрани показване само на най-важната информация (Файл + Статус)
4. **Намаляване на padding/margin** - компактифициране на таблицата с Pico.css override-и

### Приоритет
Висок (влияе на основната функционалност на интерфейса)

### Статус
✓ Завършен (коригиран преди Итерация 12)

## Реализирано решение за Bug #1

### Архитектурни решения (имплементирано)
Проблемът е в таблицата, която е твърде широка за мобилен/стандартен преглеждач. Решение:

1. **Колона "Папка"** → преместване в втори ред (или скриване на малки екрани)
   - На дървето медия, папката е вече видима в UI (Folder tree)
   - За списък с всички файлове, папката е по-малко важна от името и статуса

2. **Колона "Размер"** → съкращение или font-size намаляване
   - Сейчас показва пълния размер в GB/MB
   - Може да се съкрати с по-малко decimal places

3. **Таблица** → text-overflow: ellipsis на дълги имена
   - Файловете с дълги имена (Godzilla x Kong New Empire.mkv) ще бъдат съкратени с ...
   - Tooltip (title attribute) ще показва пълното име на hover

4. **Pico.css адаптивност** → добавяне на @media queries
   - На екрани < 768px: скриване на Папка колона
   - На екрани < 1024px: съкращаване на размер колона

### Файлове за промяна
- `templates/list.templ` (преподредба и CSS классове)
- `templates/helpers.go` (ако е нужна нова логика за съкращение)

### TDD тестове
- Тестовете не трябва да са належи на CSS/響応性, но можем да проверим:
  - HTML структурата има необходимите `title` атрибути за tooltips
  - Размерът е форматиран корректно

### Имплементирани промени
1. **list.templ** — добавени CSS класове `filename`, `folder`, `size`, `status`, `actions`
2. **CSS стилове** — `text-overflow: ellipsis` за всички колони
3. **Tooltips** — `title` атрибути за Файл и Папка колони (с пълния текст)
4. **Responsive design** — `@media (max-width: 1200px)` скрива Размер, `@media (max-width: 768px)` намалява размер на шрифт
5. **Form inline** — `display: inline` за компактни бутони
6. **Таблица** — `width: 100%` и `table-layout: auto` за адаптивна ширина

### Верификация (тестване)
1. ✓ Unit test `TestIndex_HasResponsiveTableClasses` проверява HTML класове и tooltips
2. ✓ Всички 12 тестове преминават успешно
3. ✓ Binary компилира без грешки
4. Ръчна проверка: браузъри на различни ширини ще покажат:
   - Desktop 1200px+: всички колони видими
   - Tablet 768-1200px: без Размер колона
   - Mobile <768px: компактен вид с пропорционално намален текст

## Bug #5: Липсва middleware за проверка на disk availability

### Описание

### Влияние

2. Потребител физически изваща диска
3. Следната HTTP заявка → middleware проверява диска → връща error page
4. Когато диска се върне → обновяване на страницата възстановява работата

### Приоритет
Висок (толерантност при изваждане на диска - нефункционално изискване)

### Статус
⚠ Незавършен (планирано за MVP-2)

## Bug #6: Не е имплементирано автоматично отваряне на браузъра

### Описание
Документацията (Архитектура.md, ред 168) казва: *"Отваря браузър на главната страница (`http://localhost:<port>/`)"*. Това означава че при стартиране на приложението, браузърът трябва да се отвори автоматично.

В текущата имплементация браузърът НЕ се отваря автоматично.

### Влияние
- Потребителят трябва ръчно да отвори браузър и да напише localhost:8080
- Лоша потребителска преживяност при всяко стартиране

### Потребителски сценарий
1. Потребител двойно кликва на movietracker.exe
2. Приложението стартира и **автоматично отваря браузъра** на localhost:8080
3. Списъкът с филми се показва веднага

### Технически детайли
- В main.go, след `r.Run()` стартира, използва `os/exec` за отваряне на браузъра (или използва `xdg-open` на Linux, `open` на macOS)
- URL: `http://localhost:8080/`

### Приоритет
Среден (удобство, но не критично за функционалност)

### Статус
⚠ Незавършен (планирано за MVP-1 polish)

## Bug #7: UI — Папка колона, широк бутон "Смени", бутон "Пусни"

Три свързани UI проблема в списъка с медии:

1. **Липсва колона "Папка"** — колоната съществува в HTML, но е скрита с `display:none`. Потребителят трябва да вижда в коя папка се намира файлът.

- Папката е видима колона (скрива се само на малки екрани <768px)
- Бутонът за смяна на статус показва `...` вместо "Смени"
- Кликане върху файловото име стартира медията (POST /start); колоната "Пусни" е махната

### Файлове за промяна

- `templates/list.templ` — CSS + структура на таблицата

## Bug #9: UI корекции — компактност и scroll position

### Описание
Множество UI подобрения за по-компактен вид и запазване на scroll позицията.

### Имплементирани промени
- Navbar: по-малък padding (0.2rem) и font-size (1rem)
- Заглавен ред и редове на таблицата: намален padding (0.15rem) и font-size (0.85rem)
- Статус колона: по-тясна (5rem), съкратени имена → Нова / Старт / c_Два / c_Янко / c_Лиза
- Функции колона: `flex-wrap: nowrap` — всички 6 бутона на един ред
- Файл и Папка колони: `table-layout: fixed` + `white-space: nowrap` + `text-overflow: ellipsis` — без пренасяне, показват `...` ако не стига
- Scroll position: формите използват HTMX (`hx-post`, `hx-target="closest tr"`, `hx-swap="outerHTML"`) → само редът се обновява без page reload; Папка линк използва `hx-get` + `hx-swap="none"`

### Технически детайли
- Добавен `statusShort()` helper в `templates/helpers.go`
- Извлечен `MediaRow` templ компонент (използван и от HTMX handlers)
- `StartMedia` и `ChangeStatus` handlers: при `HX-Request: true` → връщат `<tr>` HTML вместо redirect
- `OpenFolder` handler: при `HX-Request: true` → връща 200 вместо redirect

### Статус
✓ Завършен
